1. SYSTEM OVERVIEW
================================================================================

CORE FUNCTIONALITY
------------------
✓ Monthly service fee generation per unit
✓ Multiple line items per bill (base fee + utilities + penalties)
✓ Advanced penalty and waiver management
✓ Partial payment tracking within the same month
✓ Payment hierarchy enforcement (penalty → base → utilities)

KEY DESIGN PRINCIPLES
---------------------
1. Separation of Concerns: Bills (what's owed) vs Transactions (what's paid)
2. Immutable Snapshots: Historical configurations don't change
3. Query Optimization: Single SQL query for complex data
4. Payment Hierarchy: Automatic allocation following business rules

5. QUERY OPTIMIZATION
================================================================================

PROBLEM: N+1 QUERY PATTERN (SLOW)
----------------------------------

# BAD APPROACH - Multiple Database Queries

# Query 1: Fetch all payments
payments = ServiceFeePayment.objects.filter(
    service_period_month=1,
    service_period_year=2024
)  # 1 query

results = []
for payment in payments:  # Loop through 100 payments
    # Query 2-101: Fetch items for each payment
    items = payment.items.all()  # 100 queries
    
    # Query 102-201: Fetch billings for each payment
    billings = payment.billing_records.all()  # 100 queries
    
    # Query 202-301: Fetch unit data
    unit = payment.unit  # 100 queries
    
    results.append({...})

# Total: 1 + (100 × 3) = 301 queries
# Time: 2-3 seconds

SOLUTION: OPTIMIZED SINGLE QUERY (FAST)
----------------------------------------

SELECT 
    -- Payment fields
    p.id AS payment_id,
    p.unit_id,
    p.service_period_month,
    p.service_period_year,
    p.amount,
    p.remaining_amount,
    p.service_status,
    
    -- Unit & Tower info (JOINed)
    u.unit_name,
    t.tower_name,
    
    -- Resident info (JOINed)
    m.full_name AS resident_name,
    
    -- Aggregated items (JSON for efficiency)
    (SELECT JSON_ARRAYAGG(
        JSON_OBJECT(
            'item_type', i.item_type,
            'item_name', i.item_name,
            'amount', i.amount
        )
    ) FROM service_fee_management_servicefeeitem i 
    WHERE i.service_fee_payment_id = p.id) AS service_fee_items,
    
    -- Total paid (Aggregation)
    COALESCE((SELECT SUM(b.total_paid) 
              FROM service_fee_payment_details b 
              WHERE b.servicefeepaymentid_id = p.id), 0) AS total_paid

FROM service_fee_management_servicefeepayment p
INNER JOIN towers_unit u ON p.unit_id = u.id
INNER JOIN towers_floor f ON u.floor_id = f.id
INNER JOIN towers_tower t ON f.tower_id = t.id
LEFT JOIN user_member m ON p.resident_id = m.id

WHERE p.service_period_month = 1 
  AND p.service_period_year = 2024
  
ORDER BY p.created_at DESC
LIMIT 100;

# Total: 1 query
# Time: 150-200ms

PERFORMANCE COMPARISON
----------------------

Metric              | Before (N+1)   | After (Optimized) | Improvement
--------------------|----------------|-------------------|-------------
Query Count         | 301 queries    | 1 query           | 300x fewer
Response Time       | 2-3 seconds    | 150-200ms         | 10-15x faster
Database CPU        | 60-80%         | 20-30%            | 60% reduction
Memory Usage        | High           | Low               | Significant
Network Round Trips | 301 trips      | 1 trip            | 300x reduction

QUERY OPTIMIZATION TECHNIQUES
------------------------------

1. JSON Aggregation for Nested Data
   - Use JSON_ARRAYAGG() to fetch related items in single query
   - Reduces round trips between application and database

2. Subquery Aggregations
   - Calculate SUM, COUNT, MAX in database not application
   - Offload computation to database engine

3. Strategic JOIN Usage
   - INNER JOIN for required relationships
   - LEFT JOIN for optional relationships
   - Avoid unnecessary JOINs

4. Index-Aware WHERE Clauses
   - Filter on indexed columns first
   - Use exact matches when possible
   - Avoid functions on indexed columns

5. LIMIT Early
   - Apply LIMIT in SQL not application
   - Reduces data transfer

COMMON DJANGO ORM QUERIES

# Get billing for specific unit/period
payment = ServiceFeePayment.objects.get(
    unit_id=unit_id,
    service_period_month=month,
    service_period_year=year

# Get all line items
items = payment.items.all()

# Get specific item types
base_fees = payment.items.filter(item_type='base_fee')
penalties = payment.items.filter(item_type='penalty')
bill_categories = payment.items.filter(item_type='bill_category')

# Get all transactions
billings = payment.billing_records.all()

# Calculate total paid
from django.db.models import Sum
total_paid = payment.billing_records.aggregate(
    total=Sum('total_paid')
)['total'] or 0

# Check payment status
is_fully_paid = payment.service_status == 'paid'
is_partial = payment.service_status == 'partial'
is_overdue = payment.service_status == 'overdue'

IMPORTANT FORMULAS
------------------

# Total Bill Amount
total_bill = base_fee + sum(bill_categories) + penalty - waiver

# Remaining Amount
remaining = total_bill - total_paid

# Service Status
if remaining == 0:
    service_status = 'paid'
elif 0 < remaining < total_bill:
    service_status = 'partial'
elif remaining == total_bill and date.today() > due_date:
    service_status = 'overdue'
else:
    service_status = 'due'

  Payment Amount
  └─► 1. Penalties FIRST
      └─► 2. Base Service Fee
          └─► 3. Bill Categories (utilities)

STATUS LOGIC:
  remaining_amount = 0        → service_status = 'paid'
  0 < remaining_amount < amount → service_status = 'partial'
  remaining_amount = amount    → service_status = 'due'
  past due_date AND not paid   → service_status = 'overdue'
